# P2.5 schema assistance

P2.5 separates schema discovery from synchronization. Discovery reads JDY widgets, a complete source snapshot, and live Feishu field metadata; it never creates fields or records.

```bash
jdy-sync schema-propose --output reports/p2.5-field-mapping.proposed.yaml
jdy-sync schema-review --proposal reports/p2.5-field-mapping.proposed.yaml
```

Every proposal defaults to `approved: false`. Exact normalized names with compatible types are reported as `MATCH_EXISTING`; compatible missing columns are `CREATE_NEW`; unsupported or ambiguous cases are retained with an explanation.

Only explicitly reviewed proposals may be applied:

```bash
jdy-sync schema-apply \
  --proposal reports/p2.5-field-mapping.proposed.yaml \
  --confirm-schema-write
```

`schema-apply` re-reads live metadata, refuses collisions and incompatible fields, creates only approved missing fields through the documented Feishu field endpoint, re-reads the field list, and writes real field IDs into the mapping. Re-running after an interrupted field creation reconciles an existing compatible field instead of creating a duplicate. It never synchronizes records.

System fields remain separate from business proposals. Existing mappings are preserved and unapproved proposals remain protected.
